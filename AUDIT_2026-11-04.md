# Audit of the headline numbers in `bthm_merged.tex` (and `bthm_jalc.tex`)

2026-11-04. Independent audit. No `.tex`, no script and no data file was modified; everything below was
produced by re-reading the scripts and logs, and by re-computing the quantities with a separate
implementation written for this audit (`%LOCALAPPDATA%\hermes\cache\scratch\audit_*.py`).

## What "verified" means here

I wrote my own implementation of the b1=0 largest-concavity walk from the paper's own definition
(b2 = 0 iff A_{floor(m/2)} >= A_m; an epoch scans m = M … 2, cost = M − m* + 1, `M−1` on a meet),
in two forms (a literal downward loop and a vectorised scan). It was checked against the repository's
reference `q0_walk.walk_b0_fast` on **all 111,322 ensemble tapes at n = 6…12: 0 mismatches in delta
and in step count**. It also reproduces, digit for digit, every repository number it was pointed at:

| repository run | repo value | my value |
|---|---|---|
| `q4.log` n=1024, 400 tapes, seed 2026 | 0.0477 ± .0028, med .0188, P(T≤n)=.210 | 0.047694 ± .002801, med .018755, .210 |
| `q8_hist` n=1024, 2000 tapes, seed 424242 | .0540 ± .0014 (REPORT_LOWER §7) | 0.053969 ± 0.001354 |
| `q11.log` n=512, 600 tapes, seed 5150 | .0588, \|Δ≥0 .0952, \|Δ<0 .0134, P(Δ≥0)=.555 | identical to 4 dp |
| `q12.log` C, n=256, 800 tapes, seed 2026 | E[cost]/M .1332, P(cost=1) .564 | 0.133174, .5638 |
| `q12.log` G, n=4096, 3000 tapes, seed 4242 | .3807/.3293/.2490/.1897/.0910 | identical, all five |
| `qL_verify.py` n=256/512, 300 tapes, seed 2026 | P(meet) .170/.130, max meet window 27/58 | .170/.130, 27/58 |

So the re-computations are not free-hand: the generator, the ensemble and the rule all agree with the
repository's.

`bthm_merged.tex` and `bthm_jalc.tex` agree numerically: each contains 197 decimal tokens and the two
multisets are identical (only wording differs; §8 claims sit on the same line numbers, 610–845).

## Problems, in order of severity

**P1 (major). The §7 R² table is from the wrong run.** The text says "All rows come from 8000 tapes at
n=256, of which 1919 produce an output", and the following sentence compares two 8000-tape seeds
(1919 and 1939 meetings). But both columns of the table — the R² values *and* the reads/n values —
reproduce `_phase_lr_fast256.log` exactly, and that run is `tapes=2000, n_eff=495`:

    paper       s=24   32    48    64    96    128
    reads/n     19.1   24.1  32.6  39.2  48.1  52.5   <- _phase_lr_fast256: 19.14 24.10 32.63 39.20 48.10 52.46
    R2          .486   .521  .533  .553  .597  .628   <- _phase_lr_fast256: .486 .521 .533 .553 .597 .628

The 8000-tape run with 1919 meetings (`_big_s2026.log`) gives, at the same s: reads/n 18.24, 22.89,
30.78, 37.00, 45.38, 49.64 and R² .416, .442, .486, .529, .579, .580. The 1939-meeting seed
(`_big_s90210.log`) peaks at .583 (s=96). So the table is a 495-meeting curve presented as a
1919-meeting one, and its high-s columns (.597, .628) overstate what the larger sample gives (.579,
.580). The surrounding numbers (.58 at n²/ln n, second seed .583) *are* from the 8000-tape runs and
are consistent with them.

**P2. `.133` is not the measured constant of the first epoch.** `q12.log` §C gives, at 800 tapes/n,
.164 (.64), .145 (.128), **.1332 (.256)**, .130 (.512), .114 (1024), .133 (2048), .149 (4096), .135
(8192); the 3000-tape run at n=4096 gives **.1300** and the report's own headline is ".130 ± .009
(n=4096)". The paper's .133 is the n=256 row. It is inside one standard error of .130, so nothing
downstream breaks, but the sentence "the measured constant is .133" points at a small-n value.
Related: with c₀ = .133, c₀²/(2(1+c₀)) = **7.81×10⁻³**, not the 7.9×10⁻³ printed at L730; 7.9×10⁻³
would need c₀ ≈ .1345.

**P3. The Δ<0 floor is .012, not .013.** `q11.log` at n=2048 gives .0120 (and my own n=2048 sample
gives .0103); the other sizes are .0134–.0156. "…= .013 to .016" is therefore wrong at the bottom by
one unit in the third decimal. The Δ≥0 range (.090–.104) is right.

**P4. The 8192 endpoint of the ratio claim has no producing run.** No log in `probe_ologn` or
`probe_ologn2` contains E[T]/n² at n=8192; `REPORT_LOWER.md` itself writes "0.048–0.059 for
n = 1024…4096". I measured it myself (400 tapes, seed 2026): **.0480 ± .0029**, so the claim survives,
but as printed it is untraceable past 4096, and the interval is a rounding of [.0477, .0591] — my
independent 4096 sample gives .0599, just above the stated .059.

**P5. K_global at n = 7 and 9 was never computed in the repository.** `REPORT.md` §5 and
`cert_summary.json` cover n = 6, 8, 10, 11, 12, 13 only (`cert_n7.npy` and `cert_n9.npy` do not exist).
The paper's range "n = 6, …, 11" implies 7 and 9. I computed them myself: 0 pure (n−2)-subsets and
7/7 (resp. 9/9) pure (n−1)-subsets, so K_global = 6 and 8. The claim is true; the coverage was not.
(My run also reproduces the published K_global at 6, 8, 10, 11, 12, 13.)

**P6. `.428` does not exist in either manuscript.** Neither `.tex` contains the string `428` in any
R² context; the only .428 in the tree is a row of `_blk_tabn.tex` (n=256: .323/.363/.393/.388/.428), a
table block that is no longer `\input` and that `_results_canon_2026-11-04.md` itself marks as stale
("§3 的主表 … 仍是旧流程 … 需在新流程下重跑"). There is no such claim to audit.

**P7. The reproducibility paragraph points at the wrong directory.** "Everything in Section 8 is in
`probe_ologn/`, with the tables and commands in its `REPORT.md`" is false: `probe_ologn/REPORT.md`
contains no E[T], no .0540, no .133 and no Brownian p(c). All of those are in **`probe_ologn2/`**
(`REPORT_LOWER.md`, `REPORT_EPOCH_BOUND.md`, `q8_hist.py`, `q11_drift.py`, `q12_epoch_bound.py`,
`qL_verify.py`). Worse, the git repository is rooted at `paper/code/` (72 tracked files, `git ls-files`
matches no `probe*` path): neither `probe_ologn/` nor `probe_ologn2/` is version-controlled, so the
paper's claim that these scripts live "in the repository" is not true as the tree stands.

**P8 (minor). `.738` does not reproduce.** On the exact sample that reproduces every other number of
the n=512 row of `q11.log` (600 tapes, seed 5150), corr(T, Δ) = **.760**, not .738. Spearman .810,
Δ≠0 .769, log T .757 — none is .738. The paper's "+.74" is within the spread of my independent
estimates (+.72, +.76, +.77) and is fine; the report's four-digit value is not reproducible.

## Bottom line

Eleven of the twelve numbered claims are numerically sound and reproduce from scripts in the tree (two
of them only after I supplied missing sizes: n=7/9 for K_global, n=8192 for the ratio). One is not:
the §7 R² table is a 495-meeting curve presented as the 1919-meeting run. Three smaller defects: .133
is the n=256 first-epoch value rather than the n=4096 one (.130), the Δ<0 floor is .012 not .013, and
the §8 reproduction pointer names `probe_ologn/` when the numbers are in `probe_ologn2/`, which is
outside the git repository altogether.
